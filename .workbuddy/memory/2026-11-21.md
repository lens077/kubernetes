## Scorpius 2.1.1 上传失败排查（结论：非 WAF，newt 隧道间歇降速）
- 现象：`make comm-push VERSION=2.1.1` 的 `cosput` 5 MiB 分片每次 60s 被取消（edge access.log `DownstreamStatus=499`、`OriginDuration≈59.6s`、`Overhead≈0.75s`），重试 8 次全败；桶内 2.1.1 对象为 0，`latest.json` 仍是 2.1.0。
- `cosput` 用 minio-go v7.3.0，默认 `ResponseHeaderTimeout=60s`；`s3PartSize=5<<20`。50–60 KB/s 时 5 MiB 需 ~90–100s，必被 60s 掐断；198 KB 尾包 6.4s 成功。匿名 403 是 MinIO `AccessDenied`（x-amz-*），非 SafeLine/CrowdSec 拦截；Badger 只挂 pangolin UI/API 路由，不在 silo-api。
- 目标映射：`silo-api.apikv.com` = Pangolin resource 69，target 94 → `siteId=11 (k8s-cluster)` `10.10.31.240:443` internalPort 62202 → Cilium Gateway `minio-s3` HTTPRoute → `minio/minio-service:9000`（Pod 在 k3）。**不是 node2 上 127.0.0.1:9000 的 MinIO**（同一套密钥在那里报 InvalidAccessKeyId）。
- 分段测速：k1 直连集群网关 1 MiB = 0.15s / 6.8 MB/s；Mac→edge 在故障时段 1 MiB=20s、5 MiB=89s（~55 KB/s），node3→edge 27s；07:15 后连续 3 次 5 MiB ≈10s（~500 KB/s），已恢复。k3→node3 ICMP 0% 丢包、RTT 25ms；gerbil wg0 MTU 1280、TCPMSS clamp 1240、TX drop 1030。
- 已清理全部 `.diag/*` 测试对象与本地/远端临时文件。未改动任何线上配置或发布内容。
- 缓解建议：把 `s3PartSize` 降到 1 MiB（50 KB/s 时 ~20s < 60s），或在 `newUploader()` 里用自定义 Transport 把 `ResponseHeaderTimeout` 提到 5–10 min；根治需改善 edge→siteId=11 隧道吞吐（或改用集群内直连端点上传）。

## 混沌工程复现可行性评估（只读，未安装）
- 集群满足条件：k8s v1.37.2、helm v4.2.4、containerd 2.3.4，k1/k2/k3 均有 `sch_netem`/`sch_tbf`/`cls_u32` 模块（内置配置=1）；Kyverno 两条 ClusterPolicy 均为 Audit，不拦截特权 DaemonSet；无 PSA enforce 标签。
- Chaos Mesh 2.8.8（chart/appVersion 均为 2.8.8，2026-11-06 发布）官方支持 k8s 1.35–1.37，E2E 覆盖 1.35/1.37；Helm 仓库可达（200），ghcr.io `chaos-mesh/chaos-daemon:v2.8.8` manifest 200；安装需 `--set chaosDaemon.runtime=containerd --set chaosDaemon.socketPath=/run/containerd/containerd.sock`。
- Litmus 不推荐：官方镜像在 Docker Hub，k1 直连 `registry-1.docker.io` 超时；可达的 `docker.1panel.live` 需先给 3 个节点配置 containerd mirror，额外改动大且当前镜像无 mirror 配置。
- ⚠️ Cilium 风险：集群 `datapath-mode=netkit`、`bpf-lb-sock=true`、`enable-bpf-masquerade=true`，Cilium v1.20.1。社区有 NetworkChaos 在 Cilium/eBPF 下“应用成功但不生效”或延迟被放大的报告。必须先做 canary 验证（对测试 Pod 注入 delay 并实测），不能默认认为生效。
- 更贴近真实故障的注入点：node3 的 gerbil 容器（`pangolin_frontend` 网络模式，非 host）内有 `wg0` 和 `/sbin/tc`，`CAP_NET_ADMIN` 已加；可用 `docker exec gerbil tc qdisc add dev wg0 root tbf rate 400kbit ...` 复现 ~50 KB/s，清理用 `tc qdisc del dev wg0 root`。Chaos Mesh 在集群内只能验证客户端兜底，无法直接覆盖 node3 容器 netns。
