## 云主机并入 k123 集群的收益分析

- 产出 `CLOUD-HOSTS-JOIN-ANALYSIS-2026-10-20.md`（仓库根）：结论是**不建议并入**。
- 实测基线：k1/k2/k3 各 4C / allocatable 9.1GiB（合计 27.3GiB），内存实占 56/63/52%，
  CPU 仅 8%，mem limits 超卖 137%；83 Pod / 38 ns；单控制面，etcd 只在 k1；Cilium native routing +
  netkit + `devices: ens160` 钉死 + L2 announcements（VIP 池 10.10.31.240-249）。
- 云主机实测（2026-10-20）：node0 腾讯上海 6.0ms / node3 广州 25.0 / node6 广州 30.4 /
  node1 广州 29.2（Pangolin 边缘，不可动）/ node2 阿里 29.9（1.6G）/ node4 硅谷 243ms。
  全部 ping 不到 10.10.21.161 → 无 L3 通路，newt 只做 L4 反代。
- 关键论据：可加入池仅约 +6GiB 真实余量（+22%），CPU 收益无意义，云盘接不上 node-bound local PV，
  而内存大户（ES/Kafka/VM/PG）都是本地 PV 写密集，搬不动；可搬的无状态负载仅 2-3GiB。
- 推荐替代：云主机做①异地备份目标 ②OpenBao transit 自动解封 ③镜像/Chart 中转 ④集群外黑盒探测
  ⑤CI ⑥告警异地副本；集群内扩内存或把 k2/k3 提权成控制面才是解 k123 真痛点的路径。
- 备注：`211.144.221.229:6443` 对公网开放（node6 实测可拉 version），8472/10250 关闭。
