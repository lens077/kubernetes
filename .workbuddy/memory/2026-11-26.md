## casdoor 分段计时复测定案（18:15，结论：不慢）
- 方法：Mac 公网直连（`curl --noproxy '*'` 绕开宿主 54244 代理）、node3 经域名、node3 直连容器三视角，各 5–20 次分段计时。
- 数据：外网 `/login` P50=94ms / P95=114ms / max=114ms（20 次全 200，无长尾）；拆解 DNS 2ms + TCP 25ms + TLS 20ms + 服务端 25ms。node3 本机直连容器 `/login` 6–9ms、`/api/get-account` 2.4–2.9ms（10 次无长尾）；PG TLS 握手 20ms、SQL 1–2ms。node3 经域名偶发 30–40ms 抖动来自系统 resolver，不影响外部用户。

## 修复 worktree 提交钩子失效（19:53）
- **根因**：`core.hooksPath=frontend/.vite-hooks/_` 是 `vp config` 生成的**未跟踪**目录（`_/.gitignore` 内容就是 `*`），`git worktree add` 不会带过去。worktree 里该目录不存在 → git 静默跳过**所有**钩子（上次在 worktree 直接 commit 时 gitleaks/notices/doc-sync 全无输出、THIRD_PARTY_NOTICES.md 没被 add，就是这个原因，只能用主仓 `git am`+`--amend` 绕过）。
- **修复**：在 worktree `frontend/` 下跑 `CI=1 ./node_modules/.bin/vp config --hooks --no-agent`（`--no-agent` 避免它顺手改 AGENTS.md；`--hooks`+`CI=1` 避开交互提问而 exit 137）。生成 `_/` shim 后 `git hook run pre-commit` 能找到并执行。**注意** worktree 的 `frontend/node_modules` 若也没有，先软链主仓的（`ln -s /Users/lens/lens077/ecommerce/frontend/node_modules frontend/node_modules`，被 gitignore）。
- **端到端验证**：造临时改动提交 → 钩子全链真实跑（verify-public-ips → gitleaks → lint-staged → commitlint → doc-sync），无理由时 doc-sync 正确拦下 `docs/TECH.md`，加 `Doc-Impact: none` 理由后放行；验证提交 `git reset --hard HEAD~1` 清掉，worktree 干净。
- **纪律**：以后在任何 git worktree 里提交前，先确认 `frontend/.vite-hooks/_/` 存在（或 `git hook run pre-commit` 能找到 hook），否则钩子静默失效、提交绕过门禁。新 worktree 的标准动作：`ln -s <主仓>/frontend/node_modules frontend/node_modules` + `CI=1 vp config --hooks --no-agent`。
